## 接口交接：每一端由谁负责

| 调用关系 | 实现入口 | 输入 / 输出及纪律 |
|---|---|---|
| 编辑页 → M1 | authoring.create/get/save/list | Draft 独立持有 story/layout/revision；save 使用 expectedRevision，409 保留本地编辑 |
| M3/M4 → M1 | authoring.captureOwned / assertOwnedRevision | 传入公共 tx、actorId、activityId、expectedRevision；返回同修订 story/assets；不跨域直接改草稿 |
| 发布 → M3 | validationPort.validateStory | Story + ValidationBudget → CoreValidation；只有完整且 publishable 且无 error 才允许发布 |
| M2/存档/回放 → M4 | versionPort.loadVersion(tx,versionId) | 只返回经规则、结构和摘要校验的固定 PublishedSnapshot |
| M2 → M5 | eventPort.appendEvent(tx,event,requestHash,response) | 必须使用调用方 tx；不另建 PrismaClient、不吞异常；状态/事件/回执一起提交 |
| M2 → M5 | findChoiceReceipt(tx,sessionId,requestId) | 在 expectedSeq 校验前查询，载荷一致返回原结果，否则 IDEMPOTENCY_CONFLICT |
| M4 → M2 | player.readOwned / createRestored | 所有者读取与恢复分支创建均复用传入 tx；恢复 initialState 来自服务端 Save |
| M5 → M2/M4 | readForReview(tx,actorId,sessionId) + readEventStream | 同一事务按当前共享许可校验后读取；返回 initialState / finalSeq / 完整顺序事件 |
| UI → M4 | SavePort.createSave / restoreSave | 输入只含 expectedSeq、requestId、label 或分享选项；恢复返回新 Session |

兼容分发包端口的适配器集中在 `apps/api/src/ports.ts`，通过类型检查约束 Rule/Validation/Execution/Event/Version/Save 的签名。HTTP 字段和错误包装以 `packages/contracts/openapi.json` 为准。原有 26 操作保持路由和 DTO，新增第 27 项固定素材读取。Health 增补 `integrated-m4` 阶段值。

## 数据分离与低耦合规则

- Story 只描述内容与规则，Layout 只描述坐标，RuntimeState 只描述玩家当前状态；分别存储，不互相覆盖。
- 发布版本复制完整内容和素材清单，存档与事件通过 session/version 关系定位原版；不查询“最新草稿”来恢复旧记录。
- 素材路径、许可、来源、哈希属于素材目录；Story 仅引用素材 ID。当前无预置美术，纯文字功能完整。
- 所有故事差异放 fixtures 或用户草稿；禁止在规则里按标题、nodeId、钥匙名称写分支。平台数量/预算常量可以集中定义。
- 模块路由处理身份和字段，服务处理本域业务，仓储/事件适配处理持久化；跨模块走上述接口。`app.ts` 只装配公共设施与路由。
- 改 contracts 必须连同实现、调用方、样例和测试一起提交；数据库迁移由 M4 合入，不修改既有初始迁移。
