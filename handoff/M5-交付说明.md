## 三、关键设计取舍（供组员复查）

1. **错误处理沿用 M4 基线**：统一 `BusinessError`/`ensure`/`transact`（单写队列 + CAS），没有引入 starter 包里的另一套 `DomainError`，避免同一服务两套错误模型。
2. **幂等顺序**：同 `authorId+requestId` 的检查必须排在 `shareWithCreator` 门禁**之前**——玩家撤回授权后重试同一次提交，应取回原记录而不是被误判"未开启分享"。
3. **统计口径**：`eventSeq=0`（初始状态）与每条事件的 `after` 都计一次访问，所以 `n_start` 计 2 次（初始 + c_return 返回）；同一节点多次访问按次计，不按节点去重。
4. **Json 类型收窄**：Prisma 的 Json 列读出来是 `JsonValue`，在路由层用一次受控 cast 收窄回契约类型（写入侧已由 `appendEvent` 的 `EventWriter` 签名约束），并留有注释说明。
